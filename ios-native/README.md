# METRX for iPhone (Swift + SwiftUI)

The native iPhone app, built after the Android app (`../android-native`), which stays the reference for behaviour and
look. Same founder's decisions: every prototype screen, the glass look, the "Room hops" B launch animation, the laser
simulated and labelled, sign-in screens without a server, Pro shown unlocked, light theme with a dark switch, built in
parts with a stop after each.

iOS 17 and newer, iPhone only, portrait. Bundle id `uz.metrx.app`. 3D (part 4) will use RealityKit; on iOS 17 that is
an `ARView` without the camera inside SwiftUI.

## Building without a Mac

There is no Mac here: GitHub's macOS runners build the app. Every push to the `ios-native` branch that touches
`ios-native/` runs `.github/workflows/ios-native.yml`:

1. generates the Xcode project from `project.yml` with xcodegen and picks the newest iPhone simulator
   (`tools/pick_sim.py`),
2. compiles the app and both test bundles, so a source error fails within minutes with its lines listed,
3. builds the unsigned IPA (the device build), so device-only problems show early,
4. runs the unit tests (`METRXTests/`: money, the report, the PDF),
5. runs the screen tests (`METRXUITests/ScreenTests.swift`, one class per part, on one simulator; a failed
   test is retried once, for simulator stalls), which walk through the app and save a screenshot at each step,
6. records a cold start as a video.

Artifacts: `screens` (the screenshots, the video, the build, unit and screen-test logs) and `METRX-ipa`
(`METRX-unsigned.ipa`). Pushes that change only this README do not start a run.

To install on an iPhone: download `METRX-unsigned.ipa` from the run's artifacts and sign it while installing with
Sideloadly (free Apple ID; it has to be re-signed every 7 days).

With a Mac: `brew install xcodegen`, then `cd ios-native && xcodegen generate && open METRX.xcodeproj`.

## Publishing

Two workflows that run only by hand (GitHub lists a hand-run workflow only once its file is on the default branch,
`main`; the branch to build is then picked in the Run workflow menu).

**TestFlight** (`.github/workflows/ios-testflight.yml`). First, once:

1. Register the bundle id `uz.metrx.app` (developer.apple.com → Certificates, Identifiers & Profiles → Identifiers →
   App IDs, explicit, no extra capabilities), then in App Store Connect → Apps → New App make the app's record with it
   (platform iOS, any free name). The upload needs the record.
2. In App Store Connect → Users and Access → Integrations → App Store Connect API, make a team key with the **Admin**
   role and download its `.p8` file (it can be downloaded only once).
3. In the GitHub repository → Settings → Secrets and variables → Actions, add four repository secrets:
   - `ASC_KEY_ID`: the key's Key ID,
   - `ASC_ISSUER_ID`: the Issuer ID shown above the keys,
   - `ASC_KEY_P8`: the whole text of the `.p8` file (BEGIN and END lines included),
   - `APPLE_TEAM_ID`: the team ID from developer.apple.com → Account → Membership details.

Then: Actions → **iOS TestFlight** → Run workflow, or push a tag named `testflight-…` (e.g. `git tag testflight-1 && git push origin testflight-1`; the Run workflow button appears only once the file is on `main`). It archives a Release build with automatic signing (the API key lets
Xcode make the certificate and profile on the runner), exports the signed IPA (artifact `METRX-appstore-ipa`, kept 7
days) and uploads it. The build number is the workflow's run number, so every upload is new; the version is
`MARKETING_VERSION` in `project.yml`. The build shows in TestFlight after Apple's processing. A missing secret stops the
run at once with its name.

**App Store screenshots** (`.github/workflows/ios-screenshots.yml`): Actions → **iOS App Store screenshots** → Run
workflow, or push a tag named `shots-…`. It boots the biggest iPhone simulator on the runner (iPhone 17 Pro Max or 16 Pro Max, the 6.9-inch size),
sets the status bar to 9:41 with full battery and signal, and runs `METRXUITests/AppStoreShots.swift`, which makes its
sample projects through the app's screens and saves six pictures in Uzbek, Russian and English: `01-home`, `02-laser`,
`03-kitchen-3d`, `04-tiles-3d`, `05-wiring` (and `05b-wiring-3d`), `06-estimate-pdf`, named like `uz-01-home.png`.
Artifact: `appstore-screens`. The class is skipped in the usual CI run.

## Where things are

| Path | What |
|---|---|
| `project.yml` | the Xcode project (targets METRX and METRXUITests) |
| `METRX/Core/` | four languages (texts from the Android app's `strings.json`, one table for both apps), phone and number formats, settings |
| `METRX/Theme/` | the glass colours with their dark values, the fonts, text styles, the aurora background, frosted cards and blur |
| `METRX/Icons/` | the prototype's 61 icons (`IconData.swift` is generated by `tools/icons2swift.py` from the Android table) and an SVG path reader |
| `METRX/Kit/` | buttons, logo, laser button, header, switch, list rows, sheets, toasts |
| `METRX/Splash/` | the "Room hops" B launch animation (3.4 s), on the same timeline as the Android app |
| `METRX/Auth/` | welcome, sign up, log in, continue without an account, "accounts coming soon" |
| `METRX/Main/` | tab bar, Home, Projects (empty), Profile, more settings, subscription, language and laser sheets, the "Lazer sinovi" test page |
| `METRX/Laser/` | the real ZB-08 laser over Bluetooth LE (CoreBluetooth): JRT frame parser, app-wide connection with remember and reconnect, the router that sends each measurement to the waiting button, the size in focus or the readings |
| `METRX/App/` | the app model (a page stack per tab, sheet, toast, sign-in steps) and the root view |
| `METRX/Fonts/` | Plus Jakarta Sans and Manrope cut into static weights from the variable fonts (OFL), IBM Plex Sans Condensed and Mono |
